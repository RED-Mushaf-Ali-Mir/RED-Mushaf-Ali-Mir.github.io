Language models

Building a decoder-only Transformer, one attention head at a time

Attention replaced recurrence with direct, content-dependent connections between tokens. Implementing it made the data flow concrete.

15 September 20269 min readLearning source: Andrej Karpathy’s GPT lectures

Starting from next-token prediction

The training objective is simple: use the previous tokens in a fixed context window to predict the next token at every position. Token embeddings represent identity; position embeddings represent order. Their sum becomes the initial representation.

What one attention head computes

Each token produces a query, key, and value vector through learned linear projections. Query-key dot products measure which earlier tokens are relevant. Scaling stabilizes the logits before softmax.

Attention(Q,K,V) = softmax(QKᵀ / √dk)V

The weights are then used to mix value vectors. Unlike an RNN, a token can directly collect information from any allowed position in the context window.

The causal mask

During training, targets for all positions are available in one tensor. Without a mask, a position could attend to future tokens and leak the answer. Filling the upper triangle of the attention matrix with negative infinity makes softmax assign zero probability to the future.

scores = q @ k.transpose(-2, -1) * (head_size ** -0.5)
scores = scores.masked_fill(causal_mask == 0, float("-inf"))
weights = F.softmax(scores, dim=-1)
weights = dropout(weights)
out = weights @ v

Why multiple heads?

One attention head creates one pattern of token-to-token communication. Multiple heads use separate projections, so different subspaces can learn different relationships. Their outputs are concatenated and projected back into the model dimension.

The Transformer block

A decoder block alternates communication and computation:

  1. Layer normalization prepares the representation.
  2. Masked multi-head self-attention lets tokens exchange information.
  3. A residual connection preserves the previous representation.
  4. A position-wise feed-forward network transforms each token independently.
  5. Another residual connection preserves a direct path.

Dropout regularizes attention weights and projections. Stacking blocks repeatedly alternates context mixing with nonlinear feature transformation.

Training versus generation

Training evaluates many positions in parallel. Generation is autoregressive: crop to the supported context, run the model, take the final-position logits, sample one token, append it, and repeat. That repeated forward pass is why inference efficiency becomes a systems problem as models and context windows grow.

The connection I care about nextOnce the architecture works, questions move below the model: memory use, batching, attention cost, mixed precision, compilation, and caching keys and values during generation.
