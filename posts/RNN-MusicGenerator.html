Training an RNN to write Irish folk music — what I learned building a char-level LSTM

Built for MIT's Introduction to Deep Learning (Lab 1, Part 2) · 31-July-2026

Why I built this

I wanted a project that made sequence modeling feel real instead of abstract. Text generation is the usual go-to, but music has a nice property: you can immediately hear whether your model has learned anything, or whether it's just producing noise. MIT's Intro to Deep Learning course has a lab built around exactly this — train a character-level LSTM on a dataset of Irish folk songs written in ABC notation, then sample from it to generate new songs. So that became the project.

What is an RNN, actually?

A regular feedforward network sees one input and forgets it immediately. That's a problem for music (or language) because the next note depends on everything that came before it — not just the last one. An RNN fixes this with a hidden state: a vector that gets updated at every time step and carries a compressed summary of everything the network has seen so far. At each character, the model combines the new input with this running memory to make a prediction, then updates the memory again for the next step.

Plain RNNs struggle over long sequences — gradients vanish the further back you go, so the network effectively forgets things from too far in the past. LSTMs fix this with a separate cell state and a set of gates (input, forget, output) that explicitly learn what to keep, what to throw away, and what to output at each step. That's the version I used.

The model

Three components, in PyTorch: an embedding layer to turn character indices into dense vectors, an LSTM to process the sequence and maintain state, and a linear layer to project the LSTM's output back into vocabulary-size logits — one score per possible next character. 

class LSTMModel(nn.Module):
    def __init__(self, vocab_size, embedding_dim, hidden_size):
        super(LSTMModel, self).__init__()
        self.hidden_size = hidden_size
        self.embedding = nn.Embedding(vocab_size, embedding_dim)
        self.lstm = nn.LSTM(embedding_dim, hidden_size, batch_first=True)
        self.fc = nn.Linear(hidden_size, vocab_size)

    def init_hidden(self, batch_size, device):
        return (torch.zeros(1, batch_size, self.hidden_size).to(device),
                torch.zeros(1, batch_size, self.hidden_size).to(device))

    def forward(self, x, state=None, return_state=False):
        x = self.embedding(x)
        if state is None:
            state = self.init_hidden(x.size(0), x.device)
        out, state = self.lstm(x, state)
        out = self.fc(out)
        return out if not return_state else (out, state)

Tuning the hyperparameters

This was the part that made the abstract concepts click. Some of the settings I landed on: 

hidden_size = 1024        # LSTM's memory capacity
embedding_dim = 356        # how richly each character is represented
seq_length = 300           # how much context the model sees per training example
batch_size = 10
learning_rate = 1e-3       # Adam optimizer
num_training_iterations = 3000

Sequence length mattered more than I expected — too short, and the model never saw enough of a melody to learn its structure, so generated songs lost the thread halfway through. Hidden size controls how much the network can actually remember; too small and it under-fits obvious musical patterns like repeated phrases.

Where I got stuck

Generation crashed with a CUDA error: device-side assert triggered on the very first run. That error is misleading by nature — CUDA errors are asynchronous, so the traceback points to wherever the code next touched the GPU, not where the actual bug is. Once one CUDA call fails, the whole context is poisoned and every later call throws the same generic error.

Restarting the runtime and re-running on CPU surfaced the real issue: a shape mismatch. After sampling a character with torch.multinomial, the resulting tensor lost its batch dimension — shape [1] instead of [1, 1] — which broke on the second iteration of the generation loop because the hidden state was still shaped for a batched input. Reshaping the sampled index back to [1, 1] before feeding it back into the model fixed it. A one-line fix, but it took understanding what LSTM actually expects at each time step to see it.

What I actually understand now

Hidden state isn't just a technical detail — it's the entire mechanism that lets a fixed-size network handle variable-length sequences and "remember" context. I also came away with a much better intuition for why sampling matters at inference time: always picking the highest-probability character produces repetitive, degenerate output, while sampling from the full softmax distribution (via torch.multinomial) keeps generation varied and lets the model actually explore the space it learned.
