Foundations

Building a tiny gradient engine from scratch

What loss.backward() is doing: a computation graph, local derivatives, the chain rule, and careful accumulation.

20 July 20267 min readLearning source: Andrej Karpathy’s micrograd lectures

The question I wanted to answer

I had trained networks with automatic differentiation, but the convenient API hid the mechanism I most wanted to understand. So I reduced the problem to scalar values. No tensors or GPUs—only numbers connected by arithmetic operations.

Each result remembers which values produced it. That history turns an ordinary expression into a directed acyclic graph. The forward pass computes data; the backward pass walks the same graph in reverse and computes how sensitive the final output is to each intermediate value.

The Value object

class Value:
    def __init__(self, data, children=(), op=""):
        self.data = data
        self.grad = 0.0
        self._prev = set(children)
        self._op = op
        self._backward = lambda: None

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

The multiplication node only knows its local rule. If z = x × y, then ∂z/∂x = y and ∂z/∂y = x. The upstream gradient ∂L/∂z arrives in out.grad; the chain rule multiplies it by those local derivatives.

∂L/∂x = (∂L/∂z) · (∂z/∂x)

Why the order matters

A node can only push a complete gradient backward after every path from the output to that node has contributed. I first build a topological ordering with depth-first search, set the output gradient to one, and call each node’s backward rule in reverse order.

def backward(self):
    topo, visited = [], set()
    def build(node):
        if node not in visited:
            visited.add(node)
            for parent in node._prev:
                build(parent)
            topo.append(node)
    build(self)

    self.grad = 1.0
    for node in reversed(topo):
        node._backward()

The bug that taught me the most

Gradients must be added, not assigned. If one value is reused—y = x * x is the smallest example—two graph paths feed a contribution back into x. Using = silently overwrites one path; using += accumulates both.

The useful mental modelBackpropagation is not one giant derivative. It is many tiny local derivatives, evaluated in a safe order and accumulated wherever graph paths meet.

From scalars to a neural network

Once addition, multiplication, powers, ReLU, and tanh worked, a neuron was simply a weighted sum followed by a nonlinearity. A layer became a list of neurons, and a multilayer perceptron became a list of layers. Training was equally direct: run the network, compute a loss, call backward(), and update each parameter opposite its gradient.

This implementation is intentionally small, but the architecture is the same idea used by tensor libraries: record operations during the forward pass, then apply vector-Jacobian products during the reverse pass.
